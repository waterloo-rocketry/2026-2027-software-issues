# Software Subsystem GitHub Issues 2026-2027

**THIS REPOSITORY IS NOT FOR CODE. DO NOT OPEN PRS HERE**

This repository logs all tickets and technical decisions for the software subsystem members for the 2026-2027 design cycle.

Specific project details will be logged on Notion where appropriate. Docs may be committed to this repo for ease of access as well as LLM context.

## Creating an issue

Use one of the issue forms when creating work in this repository:

| Form | Use it for | Typical scope |
| --- | --- | --- |
| Project | A high-level initiative containing multiple epics | Multiple months |
| Epic | A goal or feature containing multiple stories | 1–2 months |
| Story | A user-facing outcome or feature that can be broken into tasks | 1–2 weeks |
| Task | A discrete piece of implementation, research, documentation, or setup work | A few hours |
| Bug report | Unexpected behaviour that needs investigation or correction | Varies |

Go to the repository's **Issues** tab, select **New issue**, and choose the form
that best matches the work. Each form adds its type label automatically. Add
area labels (such as `daqms`, `omnibus`, or `website`) and other useful labels
(such as `good first issue` or `bug`) as appropriate.

Use the hierarchy **Project → Epic → Story → Task** when it helps organize a
larger initiative. Link a child to its parent in the form's related-issue field
using an issue reference such as `#42`. Do not create hierarchy levels solely
for their own sake: a well-scoped task or bug may stand alone.

See [Issue template guide](ISSUE_TEMPLATES.md) for field-by-field guidance and
examples.
